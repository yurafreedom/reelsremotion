# От идеи до MP4 через Claude или GPT

Вы даёте помощнику исходники, примеры и пожелания. Он изучает материалы, составляет монтажный план, готовит файлы проекта, проверяет кадры и запускает сборку MP4. Вы проверяете смысл, темп и готовое видео. **Браузерный редактор для этого не нужен.** Установите проект по [главному README](../README.md); все команды ниже выполняются из его корневой папки.

Это развитие прежнего способа «положить файлы в папки или передать их Claude и попросить смонтировать». Здесь те же действия собраны в повторяемую последовательность.

## 1. Выберите, где работает помощник

| Вариант | Как начать | Кто запускает монтаж |
|---|---|---|
| **Claude Code** с локальным проектом | Открыть папку ReelsRemotion в Claude Code; в установленном терминальном варианте — запустить `claude` из этой папки | Claude, если ему доступно выполнение команд |
| **GPT через Codex / локальную рабочую среду** | Открыть папку ReelsRemotion как проект и начать чат с доступом к её файлам и терминалу | Помощник, если ему доступно выполнение команд |
| **Чат Claude или GPT без доступа к вашему компьютеру** | Прикрепить доступные ему материалы и описать задачу | Вы переносите полученные файлы и запускаете команды сами |

Важна не марка модели, а её доступ к **реальным файлам и выполнению команд**. Ссылка на GitHub или фраза «файл у меня на рабочем столе» сами по себе не дают такого доступа. Если вложение отправлено в чат, попросите помощника подтвердить, что он действительно может прочитать его и сохранить в проект. Если не может — положите файл вручную и укажите путь.

Установка и открытие локальных проектов описаны в официальных руководствах: [Claude Code](https://code.claude.com/docs/en/quickstart), [рабочее приложение OpenAI](https://learn.chatgpt.com/docs/desktop), [проекты OpenAI](https://learn.chatgpt.com/docs/projects). Возможности конкретного режима и разрешения вашей сессии нужно проверить перед работой.

ReelsRemotion не содержит встроенного чата и не вызывает API Claude или OpenAI. Модель работает **рядом с проектом**, читает его код и управляет имеющимися инструментами.

## 2. Подготовьте инструменты

Обязательно:

```bash
npm install
npm run check:versions
```

Для нарезки длинного видео нужны `ffmpeg` и `ffprobe`. Проверка:

```bash
ffmpeg -version
ffprobe -version
```

Если их нет, установите FFmpeg по [официальной странице](https://ffmpeg.org/download.html). На macOS с уже установленным Homebrew можно выполнить `brew install ffmpeg`.

Распознавание речи требуется только тогда, когда у вас ещё нет подходящей расшифровки с таймингами. Оно использует Python и `faster-whisper`, а не npm. Например, в терминале macOS/Linux:

```bash
python3 -m venv .venv-asr
.venv-asr/bin/python -m pip install faster-whisper
```

В Windows Python из такого окружения обычно запускается как `.venv-asr\Scripts\python.exe`; остальные инструкции с переменными окружения ниже написаны для macOS/Linux. Помощник может адаптировать их под вашу систему.

Первое распознавание скачивает модель и может занять время. Первый рендер может скачать служебный Chrome. Для просмотра интернет-шрифтов тоже нужен доступ в сеть. Шрифты системы, особенно оформление Nikulina, могут различаться на разных компьютерах.

## 3. Разложите материалы

Выберите короткое имя ролика латиницей, например `my-first-reel`. В командах ниже это имя нужно заменить на своё.

```bash
npm run reel:prepare -- my-first-reel "Мой первый ролик"
```

Команда создаёт папку ролика и несколько документов-заготовок. **Она не придумывает сценарий и не делает монтаж.** Папки `source/` и папку референсов создайте вручную в файловом менеджере или поручите помощнику.

```text
reference/
  my-first-reel/
    style-example.mp4              пример темпа и оформления
    text-example.png               пример надписей
    NOTES.md                       что именно взять из примеров

reel-input/
  my-first-reel/
    source/
      interview.mp4                длинный оригинал
      broll/                       кандидаты на дополнительные вставки
      music/                       варианты музыки
    BRIEF.md                       идея и пожелания
    SOURCE_SELECTION.md            выбранные места исходника
    source_manifest.json           точные пути и границы фрагментов
    SUBTITLE_SCRIPT.md             что сказано и что показать на экране
    EDIT_PLAN.md                   порядок фрагментов и оформление
    BROLL_PLAN.md                  где нужны дополнительные кадры
    transcript/                    текст речи и тайминги
    timeline_recipe.json           план в формате для сборщика
    timeline.json                  готовый монтажный лист
    public/
      clips/                       только вырезанные рабочие фрагменты
      media/                       только используемые картинки, музыка, вставки
    QC_REPORT.md                   результаты проверки

out/
  my-first-reel.mp4                 готовое видео
```

`B-roll` означает дополнительные кадры поверх основной речи: предмет, место, действие, иллюстрацию. Это обычные ваши файлы, а не автоматически сгенерированное видео.

**Не кладите полный выпуск и референсы в `public/`.** Рендер копирует содержимое выбранной `public/` во временную сборку. Туда должны попадать только материалы, реально используемые в ролике. Для примеров допустима и общая папка `reference/`, но отдельная подпапка помогает не спутать задания.

У `reel:prepare` остались значения из старого проекта: `video1219377731.mp4` и историческая расшифровка. Помощник должен заменить `source_authority` и пути в `source_manifest.json` на ваши. Готовые `preproduction_eight.json`, `compose/asr_reel*.py` и старые сборщики относятся к конкретной серии; запускать их как универсальный мастер нового ролика нельзя.

## 4. Запишите идею простыми словами

В `BRIEF.md` достаточно такого задания:

```text
Тема: почему люди откладывают важный разговор.
Зритель: человек, который узнает себя в этой ситуации.
Цель: одна понятная мысль и сильная последняя фраза.
Длительность: примерно 30–45 секунд.
Источник: reel-input/my-first-reel/source/interview.mp4.
Референсы: reference/my-first-reel/.
Из первого примера взять темп, из второго — размер и цвет текста.
Язык субтитров: русский.
Музыка: тихо, речь должна быть хорошо слышна.
Нельзя: обрезать слова и менять смысл высказывания.
Результат: MP4 1080×1920, 30 fps + монтажный лист + материалы для правок.
```

Точный сценарий заранее необязателен: попросите помощника предложить его по вашему исходнику. Но сценарий **должен появиться до финальной сборки**: какие фрагменты идут друг за другом, где надписи, где акцент и чем заканчивается ролик. Если сценарий уже готов, приложите его и обозначьте, какие части можно менять.

## 5. Получите расшифровку и выберите фрагменты

Попросите помощника:

1. Проверить длительность и звук исходника через `ffprobe`.
2. Прочитать имеющуюся расшифровку или распознать речь.
3. Найти фрагменты, подходящие к идее, и указать время начала и конца.
4. Проверить, что начало и конец не обрезают слово и что смысл не потерян.
5. Записать выбранные места и буквальные цитаты в документы ролика.

Для простого черновика в репозитории есть старая утилита:

```bash
.venv-asr/bin/python asr_to_timeline.py reel-input/my-first-reel/source/interview.mp4 --lang ru --model small --out reel-input/my-first-reel/transcript/asr-draft.json
```

Это **старый черновик сцен с распознанными словами и примерной расстановкой**, а не готовый монтаж и не автоматическая подстановка исходного видео. Для длинного выпуска разумнее распознавать выбранный участок или готовить исходную расшифровку отдельно. Режим `--words-only` этой утилиты тоже не создаёт формат `segments[]`, который ожидает `reel:quote`.

Для производственного процесса помощник готовит исходную расшифровку вида `{ "segments": [{ "id", "start", "end", "text", "words": [...] }] }` со временем в секундах. Если она уже существует, можно вывести отрывок:

```bash
npm run reel:quote -- 00:01:00 00:01:30 --asr reel-input/my-first-reel/transcript/native-asr.json --format text
```

Всегда указывайте `--asr` для своего источника: значение по умолчанию относится к старому выпуску. Один SRT обычно даёт время фраз; он не даёт точного времени каждого слова. Распознавание нужно проверять на слух; автоматического надёжного разделения по говорящим здесь нет.

## 6. Утвердите монтажный план

Попросите показать вам:

- Начальную фразу, основную мысль и финал.
- Список исходных фрагментов с таймкодами.
- Текст надписей, оформление и места вставок.
- Что именно заимствуется из референса.
- Сомнительные слова, переводы и стыки, которые требуют вашего решения.

В `SUBTITLE_SCRIPT.md` должны различаться **буквальная речь** и **текст на экране**. Переведённые субтитры привязываются к соответствующим фразам исходника, а не к выдуманным моментам произнесения слов на другом языке.

Сборщик `reel:timeline` принимает `timeline_recipe.json` только со статусом `approval_status: "APPROVED"`. Это означает, что выбранный план согласован; сама программа не проверяет, что его действительно прочитал человек. Помощник должен опираться на ваше реальное согласование. Если вы заранее поручили собрать ролик строго по приложенному утверждённому сценарию, это уже исходное разрешение на его реализацию.

## 7. Поручите помощнику подготовить и собрать проект

Порядок действий для помощника:

1. Заполнить документы и `source_manifest.json`, включая реальные пути к исходникам, цитаты и границы.
2. Подготовить данные речи в `transcript/words_source.json`, а при переводе — `translation_phrase_map.json` в формате существующего процесса.
3. Вырезать выбранные куски в `public/clips/` внутри папки ролика.
4. Положить выбранные картинки, музыку и дополнительные видео в его `public/media/`.
5. Создать `timeline_recipe.json`, ориентируясь на `reel-input/_templates/timeline_recipe.example.json`, и согласованные настройки стиля.
6. Собрать `timeline.json`, проверить данные и тестовые кадры, исправить найденные проблемы.
7. Собрать MP4 и проверить его.

Команды выполняются **после подготовки соответствующих данных**, а не сразу после пустого `reel:prepare`:

```bash
npm run reel:validate -- my-first-reel
npm run reel:extract -- my-first-reel
npm run reel:timeline -- my-first-reel
npm run reel:validate -- my-first-reel --render
npm run reel:render -- my-first-reel out/my-first-reel.mp4
```

Если `reel:extract` отказывается перезаписывать отличающийся готовый фрагмент, нужно проверить причину и выбрать новое имя или новую версию. Не обходите ошибку вслепую.

Готовых универсальных дизайнерских шаблонов здесь немного: компилятор исторически развивался под серию Nikulina. Если ваш монтаж не выражается его рецептом, помощник может подготовить **v3 `timeline.json` напрямую**, опираясь на `src/types.v3.ts` и контракт. Для такого самостоятельного монтажного листа не требуется притворяться, что заполнен весь редакционный пакет:

```bash
REEL_PUBLIC_DIR="$PWD/reel-input/my-first-reel/public" npm run render:reel -- reel-input/my-first-reel/timeline.json out/my-first-reel.mp4
```

Эта команда проверяет формат монтажного листа и запускает рендер, но не заменяет проверки исходных цитат и смысла. Она не требует открытого браузерного редактора.

## 8. Проверьте до и после рендера

Проверочный кадр и набор кадров можно получить без редактора:

```bash
REEL_PUBLIC_DIR="$PWD/reel-input/my-first-reel/public" npm run check -- reel-input/my-first-reel/timeline.json 30
REEL_PUBLIC_DIR="$PWD/reel-input/my-first-reel/public" npm run check -- reel-input/my-first-reel/timeline.json sheet
```

Первый результат по умолчанию — `check.png`, второй — `sheet.png` и папка `sheet_frames/` в корне. Эти имена используются повторно; для нескольких роликов попросите помощника сохранять проверочные изображения в отдельные папки. Не запускайте несколько `compose/run.mjs` одновременно без разных `COMPOSE_TMP`: по умолчанию у них один временный файл.

Посмотрите кадры: читается ли текст, не закрывает ли лицо, не выходит ли за экран. Затем посмотрите и **прослушайте весь MP4**. Набор картинок не подтверждает правильный звук и стыки.

```bash
ffprobe -v error -show_streams -show_format out/my-first-reel.mp4
```

Помощник должен сообщить, что проверил реально: например, размер, длительность, наличие аудиодорожки, выбранные кадры. Фраза «рендер завершился» не означает, что ролик художественно готов или прослушан человеком.

## 9. Внесите правки и сохраните результат

Правки удобно формулировать так: «на 00:07 надпись закрывает лицо», «убери паузу после второго предложения», «финальная фраза обрывается», «музыку тише». Попросите сохранять версии `v1`, `v2`, а не перезаписывать единственный результат.

В конце у вас должны остаться:

- MP4 в `out/`.
- `timeline.json` и, если применялся сборщик, `timeline_recipe.json`.
- Все используемые файлы из папки `public/` конкретного ролика.
- Сценарий, расшифровка, привязка к исходнику и отчёт о проверке.

Папка `out/` исключена из Git: загрузка кода в репозиторий сама по себе не сохраняет там готовые видео.

## Если у GPT или Claude есть только чат

Такой чат может помочь придумать структуру, написать сценарий и подготовить файлы по переданному контексту. Он не сможет запустить ваш локальный рендер без соответствующего инструмента.

1. Положите исходники и референсы в папки из шага 3 самостоятельно.
2. Передайте чату задание, доступные ему файлы или кадры, расшифровку, `src/types.v3.ts`, `src/types.ts` и контракт. Одних названий файлов недостаточно для анализа содержимого.
3. Попросите выдать конкретный `timeline.json` и список необходимых медиа с точными путями; для нарезки — конкретные команды по вашему исходнику.
4. Сохраните ответ как настоящий JSON-файл без Markdown-ограждений. Выполните подготовку медиа и команду `render:reel` из шага 7 в своём терминале.
5. Передайте чату ошибки или проверочные кадры и повторите правки.

Это более ручной вариант. Для полного цикла «попросил → помощник сам собрал файл» нужна среда с доступом к проекту и командам.

## Передать монтаж в браузер и обратно

**Из помощника в редактор:**

1. Сохраните копию исходного монтажного листа.
2. Учтите: браузер обслуживает **общую `public/` в корне**, а производственный рендер часто использует **`reel-input/<имя>/public/`**.
3. Попросите помощника скопировать материалы ролика в отдельную папку, например `public/reels/my-first-reel/`, и сделать копию монтажного листа для редактора с исправленными путями: `clips/a.mp4` → `reels/my-first-reel/clips/a.mp4`, `media/music.mp3` → `reels/my-first-reel/media/music.mp3`. Нужны замены во всех используемых дорожках. Исходную версию сохраняйте.
4. Запустите `npm run dev` и импортируйте эту копию через `Import JSON…`.

Сам импорт JSON не копирует медиа. Указание `REEL_PUBLIC_DIR` для команды рендера также не меняет папку браузерного редактора.

**Из редактора помощнику:** экспортируйте `timeline.json`, передайте его и пути к медиа. Его можно рендерить с корневой `public/`:

```bash
npm run render:reel -- reel-input/my-first-reel/editor-timeline.json out/my-first-reel-edited.mp4
```

Здесь предполагается, что скачанный JSON вручную сохранён как `reel-input/my-first-reel/editor-timeline.json`. Для независимого пакета помощник должен собрать используемые медиа в отдельную `public/` и поправить пути.

Не запускайте `reel:timeline` поверх единственного файла с ручными правками: компилятор заново строит монтаж из рецепта и может заменить эти правки. Сохраните отдельную версию и попросите перенести необходимые изменения в рецепт.
